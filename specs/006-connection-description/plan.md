# Implementation Plan: Optional Connection Description in Place of the Form ID

**Branch**: `006-connection-description` | **Date**: 2026-11-05 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/006-connection-description/spec.md`

**Note**: this checkout's `.git` points to a worktree path that doesn't exist here, so git couldn't
confirm the branch. `setup-plan.sh` resolved the feature from `.specify/feature.json`.

## Summary

A connection's "Form ID" (`servicebw_form`) becomes an optional free-text **description**, under
that name everywhere, and no longer blocks step 1 or publishing.

**Technical approach** (research R1–R7):
- **Storage**: one migration renames the column. The values carry over unchanged (R1).
- **Checks**: one `clean_description()` for every path: trim, empty allowed, at most 500
  characters (R2).
- **API**: `description` in every schema, with a default of `''` in the create bodies and no
  alias (R3). The description creates no revision, as before (R4).
- **Local drafts**: format 2. The store's existing "remove invalid records" removes the old
  ones (R5).
- **Screens**: the overview and the details header show the description on one line, cut with
  "…", and nothing when it is empty (R6). Step 1 shows "Description - Optional" with new help
  text (R7).

## Technical Context

**Language/Version**: Python 3.13 (backend); TypeScript with React 19 (frontend).

**Primary Dependencies**: unchanged (FastAPI, SQLAlchemy 2 sync, Alembic, Pydantic 2; React Router
7, KERN, Tailwind CSS 4).

**Storage**: PostgreSQL, a column rename in `form_connections`. Browser `localStorage`, local
draft format 2.

**Testing**: pytest (a practice, run anyway) for the API paths. Vitest (the gate) for the editor's
validation, the list helper and `utils/localDrafts/`. Manual scenarios V1–V6 in
[quickstart.md](quickstart.md).

**Target Platform**: unchanged: evergreen desktop and mobile browsers, and Linux containers that
run `alembic upgrade head` on start.

**Project Type**: web application (React SPA, FastAPI backend, PostgreSQL).

**Performance Goals**: none new. The rename is a metadata change in PostgreSQL.

**Constraints**:
- No URL, revision, rule set or EUDIPLO call changes (FR-010, SC-005).
- Every value carries over unchanged (FR-007).
- Old local drafts are dropped, not converted (FR-009).
- WCAG 2.1 AA: the whole text reaches assistive technology (FR-006).

**Scale/Scope**: a rename across about 40 files:
- **Backend**: 1 migration, and changes to `models.py`, `schemas.py`,
  `services/form_connections.py`, `services/drafts.py` and 7 test files.
- **Frontend**: types, the editor (step 1, reducer, validation, payloads), the list row, the
  details pages, `TopBar`, `TextField` (`optional` prop), `utils/localDrafts/`, and their tests.

**Open points**: none. One check while coding: the details header's layout at 320 to 1440px
(R6).
