# Tasks: Port the redesigned UI (KERN Revamp) and remove the old design

**Input**: Design documents from `/specs/008-kern-revamp-redesign/`: [plan.md](plan.md) ("Rules for
`/speckit-tasks`"), [spec.md](spec.md) (US1–US5, FR-001–FR-052, SC-001–SC-007, the Clarifications),
[research.md](research.md) (R1–R15), [data-model.md](data-model.md), [contracts/ui-screens.md](contracts/ui-screens.md)
(L1–L4, S1–S22, the coverage index), [design-notes.md](design-notes.md) (§1 overlay, §2 component
decisions, §3 patterns, §4 motion, §5 verification tables, §7 removal checklist), [quickstart.md](quickstart.md) (V1–V13).

**Prerequisites**: `npm install` at the root and `uv sync` in `backend/` (research R14); the dev
server `npm run dev -w frontend` on 5173 with a test account; the Figma audit's inventory
(`figma-audit/units.md`, `figma-audit/units/U##.md`, `figma-audit/kit/`) read by the task agents.

**Tests**: no new test tasks beyond what the plan prescribes: pure helpers get a `*.test.ts` beside
them, existing tests change only for an adopted item (the task names it), the backend's pytest and
the MCP's tests are updated by the C tasks. No DOM tests, no `vitest.config.ts`, no `pytest.ini`.

**Organization**: the eleven phases of plan.md's "Rules for `/speckit-tasks`" (research R12; one chat
per phase, US3 two or three): Foundations → Copy outside the frontend → Shared components → Layouts →
US1 → US2 → US3 → US4 → US5 → Removal → Verify and close.

## Format: `[ID] [P?] [Story] [Level] Description`

- **[P]**: can run in parallel: different folders, no dependency on an unfinished task. **Figma
  caps the parallel agents at three**; the waves and batches of a phase are in its "Delegation"
  section.
- **[Story]**: US1–US5 for the story phases; none for Foundations, Copy, Shared components,
  Layouts, Removal and Verify.
- **[Level]**: who takes the task in `/speckit-implement`; where a task's `agent:` field says
  otherwise, the marker wins and the task's text stays as written.
  - **[medium]**: `speckit-task-medium`: mechanical or fully specified work: moves, renames,
    config, mirrors of existing types, glue code, documentation, tests of behaviour that already
    exists.
  - **[high]**: `speckit-task-high`: new logic that needs design within the task: algorithms,
    state machines, retry loops, parsers, workers, pages with several states, the per-node loop
    against Figma.
  - **[xhigh]**: `speckit-task-xhigh`: a mistake is costly and tests written alongside the code
    are unlikely to catch it: authentication, authorization, tokens and secrets, concurrency and
    row locks, transactions around external calls, refactors across many files that must not
    change behaviour, rules that other specs depend on.
  - **[lead]**: the coordinator does it itself: the checkpoints, and tasks that settle an open
    decision in the spec documents that later tasks depend on.
- **Every UI task line carries**: the screen (L#, S#), the units and frames it builds from
  `contracts/ui-screens.md`, the items it meets (F#, W#, C#, FR, CLAR #n; a lettered FR such as
  `FR-029c` names a clause as `figma-audit/requirements.md` indexes it), the files it edits, the
  agent (`speckit-task-high`, `speckit-task-xhigh`, `speckit-task-medium`) and `verify:` the
  verification table it appends to design-notes §5 (§5.1 for a component, §5.2 for a screen).
- A task reads at most about ten Figma nodes (about twenty calls); frames cited as "not read"
  are decided items (F1, F2, F23) whose inventory in `figma-audit/units/` stands.

## Path Conventions

Web application (constitution): `frontend/src/{api,components,pages,hooks,utils,workers}/`,
`rules/src/`, `mcp/src/` + `mcp/plugin/`, `backend/app/` + `backend/tests/`. Paths below are from
the repository root. Components are rebuilt **in place under their names**; a new file appears only
where the plan's source tree lists one (`DocumentsStep/`, `StatusBand.tsx`, `WelcomePage.tsx`,
`EditDataDialog.tsx`, `useRememberedHomepage.ts`, the leave-flow reducer).

## Rules every task follows (plan.md, "Rules for `/speckit-tasks`")

- **Figma decides layout, styling and wording; the baseline (specs 001–007) decides behaviour**; a
  difference cites a decided item. **A frame that changed since the audit is not built**: the task
  stops on that node, lists it as UNCERTAIN in its report, and the coordinator takes it to clarify
  (FR-004).
- **The per-node loop** (quickstart "The per-node verification loop", `docs/FIGMA-WORKFLOW.md`
  §3–§4): `get_design_context` + `get_screenshot` per node, `browser_resize` to the frame's width
  plus the scrollbar gutter (1455 px for 1440), the font check, the numeric check, the screenshot
  comparison; the table rows (`frame | state | element | property | Figma | actual | result`) go
  into design-notes §5 (template there); a unit is done when no row is open.
- **AA contrast**: a task that meets a failing Revamp text pair fixes it to the nearest passing value
  and adds the row to design-notes §1.5 (CLAR 2026-11-06 #2, W1).
- **Behaviour stays the baseline's**: a reducer, hook or pure helper keeps its tests passing; a test
  changes only for an adopted item, named in the task. Nothing new is logged: no `console.*` in
  `rules/src/checks/`, `rules/src/personas/`, `frontend/src/workers/`, the hooks or
  `utils/localDrafts/`; findings and personas are never stored or sent (FR-047).
- **Gates after every task**: `npm run lint && npm test && npm run build` from the root for a Node
  package; `uv run ruff check --fix . && uv run ruff format . && uv run mypy app/ scripts/ tests/`
  and `DATABASE_URL=…template_db_test uv run pytest` in `backend/` for a backend change. **Nothing
  commits** (git is read-only here; the user commits on the other machine).
- **Copy**: the design's text word for word, typographic apostrophes (’), interpolations keep their
  variables, sample data is not copy (FR-002); the texts of the C items come from phase 2.
